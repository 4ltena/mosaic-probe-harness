# 設計メモ

画像を渡すと「モザイクが必要な部位が、写っていない、または十分に処理されている確率 `p_ok`」を数値 1 個で返す。判定のしきい値は持たない。

## 構成

```
呼び出し側 ──(REST / MCP)──> ハーネス(Node, TypeScript) ──(HTTP)──> llama-server(llama.cpp)
                             形式判定・レイヤー描画・確率の計算          VLM（画像入力、logprobs）
```

- ハーネスだけを LAN に出す。`llama-server` は `127.0.0.1`（複数台のときは専用リンクの IP）に限る。
- 画像は保存しない。ログに画像・base64・キーを出さない。

## 確率の作り方

1. 描画ごとに、減色なしの8bit RGB PNG とモザイクの判定基準を各モデルへ送る。透過部分は白で合成し、通常判定と切り出し再判定のどちらも PNG を使う。回答語は `none`（対象なし）、`processed`（処理済み）、`forgot`（未処理・処理不足）、`nori`（黒い帯・枠）とする。
2. 各接続先の初回利用時に `/tokenize` で4語の先頭トークンを確かめる。`max_tokens: 1`、思考オフで、1トークン目の上位20件の `logprobs` を得る。4語の質量の合計が0.9以上の場合に、モデルごとに合計1へ正規化する。
3. モデルの4語の確率を重み付き平均し、次の式を描画ごとに適用する。

   ```text
   okMass = P(none) + P(processed)
   ngMass = max(P(forgot), P(nori))
   q = ngMass / (okMass + ngMass)
   p_ok = 1 - cal(q)
   ```

4. `cal` は v1.1 用の Platt 較正。ファイルが無ければ恒等を使う。`okMass >= ngMass` なら `judgment` は `ok`。それ以外は `forgot`、`nori` のうち大きい方で、同率は `forgot`。`confidence` は選んだ項目の確率。
5. `p_ok` が最小の描画を採用する。`detail` の `classes` は統合後の `ok`、`forgot`、`nori`。`per_model` は同じ描画のモデル別の4語の確率。

### 前段の検出（`DETECT=1`、既定オフ）

描画ごとの候補に、検出した部位の切り出しを足す。全体と切り出しを同じ判定器・同じ式で判定し、**候補の中で `p_ok` が最小のもの**を採る（順位は `p_ok` の昇順、次に描画の番号、次に候補の番号。同じなら全体が先）。較正が単調増加（`a > 0`）なので、どれか 1 つでも NG なら NG になり、`DETECT=0` の値以下になる。`judgment`・`classes`・`per_model`・`render` は、選ばれた 1 つの候補からそろって出る。`render` は「<描画名>の切り出し k」になる。`detail=1`（`fields` なし）では、選ばれた候補の描画の画風の分類と検出の箱を `detect` で返す（目視の確認用）。

- 検出器（ONNX）は部位の位置を見つけるだけで、判定には関わらない。検出しなかったことを `ok` の根拠にはしない（見逃しを増やすため。切り出しは候補を足すだけ）。
- 画風の分類器（任意）は、写真用とイラスト用のどちらの検出器を使うかを選ぶ。検出器が 1 つなら分類器は使わない。
- 切り出しは再判定（`RECHECK`）に渡さない。再判定は全体の最悪の描画だけに動く（探す範囲が切り出しに狭まって、`DETECT=0` より甘くなるのを防ぐ）。最終の `p_ok` は、再判定後の全体の結果と切り出しの最悪のうち低い方で、同じ入力の `DETECT=0` の値以下になる。
- 検出・切り出し・切り出しの判定のどれかが失敗したら、要求全体を失敗にする（数値を返さない）。

## Pi の使い方

- 土台は `@earendil-works/pi-ai` と `pi-agent-core`（MIT）。**Pi 本体は改造せず、依存として使う。**
- 通常の分類は `llama-server` の `/v1/chat/completions` へ直接問い合わせる。
- `pi-agent-core` の `Agent` は再判定（`RECHECK=1`、既定オフ）だけに使う。境界付近の画像を領域ごとに切り出して判定し、**`p_ok` を下げることしかしない**。
- **モデルに渡すツールは自作の `crop` だけ。** Pi の標準ツール（read / bash / edit / write など）は導入もしない。`tests/tool-scope.test.ts` で固定している。
- 前段の検出器（ONNX）は、モデルに渡すツールではない。ハーネスが切り出しを作り、同じ判定器へ送る。再判定の `crop` ツールとは別の経路で、ツールの範囲は増えない。

## レイヤー安全

モザイクが別レイヤーだと、非表示や削除で解除できる。PSD は「見えているとおり」「非表示も表示」「モザイク名のレイヤーを非表示」「可視レイヤーを 1 枚ずつ外す」を判定し、**最小の `p_ok`** を返す。1 件でも失敗したら全体を失敗にする。限界は README の「PSD 合成の制限事項」。

## 複数台

`JUDGES` の各要素にモデルと接続先を設定する。同じモデルの複製は同じ要素の `urls` に入れる。タスクは描画とモデルの組み合わせで、同時実行数はモデルごとの共有プールが制限する。クライアントの切断後は待機中のタスクを取り消す。

複製のうち失敗した台は15秒外し、同じモデルの別の台で1回だけ再試行する。すべてのモデルの結果が揃った描画に対して式を適用する。

GIF・WebP は既定で10秒・100フレームまで、TIFF は100ページまで。PSD は候補数が `MAX_RENDERS`（既定32）以内なら全候補を判定する。上限超過は `too_large` とし、PSD では `psd_render_limit` と必要件数・設定上限を返す。描画は必要になった時点で生成する。

## 失敗の扱い

どの経路でも、失敗のときに数値を返さない。呼び出し側がエラーを `0` や `1` で埋めて続行することを防ぐため。MCP は `isError: true`（HTTP は 200）、REST は `{"error": …}` とステータスで返す。

## 非目標

OK/NG の判定、バッチ処理、画像の保存、判定理由の返却、TLS の終端（リバースプロキシは接続元 IP の判定を崩すので置かない）。

前段の検出を足しても、非目標とは矛盾しない。既定の応答と `fields` の形は変えない。`detect` は検出器の出力をそのまま返すだけで、判定理由ではない。画像は保存せず、ログに座標を出さない。しきい値も持たない。

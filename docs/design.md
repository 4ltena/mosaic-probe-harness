# 設計メモ

画像を渡すと「モザイクが必要な部位が、写っていない、または十分に処理されている確率 `p_ok`」を数値 1 個で返す。判定のしきい値は持たない。

## 構成

```
呼び出し側 ──(REST / MCP)──> ハーネス(Node, TypeScript) ──(HTTP)──> llama-server(llama.cpp)
                             形式判定・レイヤー描画・確率の計算          VLM（画像入力、logprobs）
```

- ハーネスだけを LAN に出す。`llama-server` は `127.0.0.1`（複数台のときは専用リンクの IP）に限る。
- 画像は保存しない。ログに画像・base64・キーを出さない。

## 確率の作り方

1. 描画ごとに、減色なしの8bit RGB PNG とモザイクの判定基準を各モデルへ送る。透過部分は白で合成し、通常判定と切り出し再判定のどちらも PNG を使う。回答語は `none`（対象なし）、`processed`（処理済み）、`forgot`（未処理・処理不足）、`nori`（黒や白の帯・線・枠・塗り。白線も含む）とする。
2. 各接続先の初回利用時に `/tokenize` で4語の先頭トークンを確かめる。`max_tokens: 1`、思考オフで、1トークン目の上位20件の `logprobs` を得る。4語の質量の合計が0.9以上の場合に、モデルごとに合計1へ正規化する。
3. モデルの4語の確率を重み付き平均し、次の式を描画ごとに適用する。

   ```text
   okMass = P(none) + P(processed)
   ngMass = max(P(forgot), P(nori))
   q = ngMass / (okMass + ngMass)
   p_ok = 1 - cal(q)
   ```

4. `cal` は v1.1 用の Platt 較正。ファイルが無ければ恒等を使う。`okMass >= ngMass` なら `judgment` は `ok`、それ以外は `ng`（NG の種類は返さない）。`confidence` は選んだ項目の確率。
5. `p_ok` が最小の描画を採用する。`detail` の `classes` は統合後の `ok`（okMass）と `ng`（ngMass）。`per_model` は同じ描画のモデル別の値を同じ式でまとめた `ok`・`ng`。

### 前段の検出（`DETECT=1`、既定オフ）

描画ごとの候補に、検出した部位の切り出しを追加します。全体と切り出しを同じ判定器・同じ式で判定し、**候補の中で `p_ok` が最小のもの**を採用します。

- **候補の順位規則**: `p_ok` の昇順 → 描画の番号 → 候補の番号（同値なら全体が先）。
- **単調性と出力の一貫性**: 較正が単調増加（`a > 0`）であるため、どれか 1 つでも NG なら NG になり、`DETECT=0` の値以下になります。`judgment`・`classes`・`per_model`・`render` は、選ばれた 1 つの候補からそろって出力されます（切り出しが選ばれた場合、`render` は「`<描画名>の切り出し k`」）。
- **補助情報（`detect`）**: `detail=1`（`fields` なし）では、選ばれた候補の描画の画風分類と検出の箱を `detect` で返します（目視の確認用）。
- **検出器の役割**: 検出器（ONNX）は部位の位置を見つけるだけで、判定には関わりません。検出しなかったことを `ok` の根拠にはしません（見逃しを増やすため。切り出しは候補を足すだけです）。
- **画風分類器（任意）**: 写真用とイラスト用のどちらの検出器を使うかを選びます。検出器が 1 つなら分類器は使いません。
- **再判定（`RECHECK`）との関係**: 切り出しは再判定に回さず、再判定は全体の最悪の描画だけに動かします（探索範囲が切り出しに狭まって `DETECT=0` より甘くなるのを防ぐため）。最終の `p_ok` は「再判定後の全体の結果」と「切り出しの最悪」のうち低い方となり、同じ入力の `DETECT=0` の値以下になります。
- **エラー時の扱い**: 検出・切り出し・切り出し判定のいずれかが失敗した場合は、要求全体を失敗にします（数値を返しません）。

## Pi の使い方

- 土台は `@earendil-works/pi-ai` と `pi-agent-core`（MIT）。**Pi 本体は改造せず、依存として使う。**
- 通常の分類は `llama-server` の `/v1/chat/completions` へ直接問い合わせる。
- `pi-agent-core` の `Agent` は再判定（`RECHECK=1`、既定オフ）だけに使う。境界付近の画像を領域ごとに切り出して判定し、**`p_ok` を下げることしかしない**。
- **モデルに渡すツールは自作の `crop` だけ。** Pi の標準ツール（read / bash / edit / write など）は導入もしない。`tests/tool-scope.test.ts` で固定している。
- 前段の検出器（ONNX）は、モデルに渡すツールではない。ハーネスが切り出しを作り、同じ判定器へ送る。再判定の `crop` ツールとは別の経路で、ツールの範囲は増えない。

## レイヤー安全

モザイクが別レイヤーだと、非表示や削除で解除できる。PSD は「見えているとおり」「非表示も表示」「モザイク名のレイヤーを非表示」「可視レイヤーを 1 枚ずつ外す」を判定し、**最小の `p_ok`** を返す。1 件でも失敗したら全体を失敗にする。限界は README の「PSD 合成の制限事項」。

## 複数台

- `JUDGES` の各要素にモデルと接続先を設定します。同じモデルの複製は同じ要素の `urls` に入れます。
- タスクは「描画 × モデル」の組み合わせで、同時実行数はモデルごとの共有プールが制限します。クライアント切断後は待機中のタスクを取り消します。
- 複製のうち失敗した台は 15 秒間プールから外し、同じモデルの別の台で 1 回だけ再試行します。すべてのモデルの結果が揃った描画に対して式を適用します。

## 入力上限と遅延描画

- **アニメーション・複数ページ**: GIF・WebP は既定で 10 秒・100 フレームまで、TIFF は 100 ページまで。
- **PSD 候補上限**: 候補数が `MAX_RENDERS`（既定 32）以内なら全候補を判定します。上限超過は `too_large` とし、PSD では `psd_render_limit` と必要件数・設定上限を返します。
- **遅延描画**: 各描画は判定が必要になった時点で生成します。

## 失敗の扱い

どの経路でも、失敗のときに数値を返さない。呼び出し側がエラーを `0` や `1` で埋めて続行することを防ぐため。MCP は `isError: true`（HTTP は 200）、REST は `{"error": …}` とステータスで返す。

## 非目標

次の機能はスコープ外とする。

- OK/NG の最終判定（しきい値の保持）
- バッチ処理
- 画像の保存・判定理由の返却
- TLS の終端（リバースプロキシは接続元 IP の判定を崩すため置かない）

> [!NOTE]
> 前段の検出（`DETECT=1`）を追加しても非目標とは矛盾しない。既定の応答と `fields` の形式は変えず、`detect` は検出器の出力をそのまま返すだけで判定理由ではない。画像は保存せず、ログに座標を出さず、しきい値も持たない。
